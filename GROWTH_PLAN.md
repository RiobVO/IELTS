## Статус волны 1 (2026-08-04)

Закрыта целиком, включая независимое ревью (Codex, read-only) и живой прод-прогон
реферального цикла на временной паре аккаунтов (созданы, проверены, удалены; Elo
затронутого теста восстановлен). Ревью нашло 4 дефекта — все подтверждены по коду и
исправлены в `087ce7b`:

1. ранний (soft) чек капа судил по бонусу из незалоченного снапшота профиля — при
   параллельно закоммиченной награде он мог ложно отказать; теперь судит по
   максимально возможному лимиту, решение принимает только транзакционная проверка;
2. кнопка Share открывала окно ПОСЛЕ await — мобильные popup-блокеры её глушили, а
   reject действия уводил мимо фоллбэка (`finally` без `catch`);
3. предиктор клал слабый тип в ответ гостю, хотя UI обещает его после регистрации;
   заодно IP перестал уходить в аналитику сырым;
4. регистрация теряла `next`, и «Unlock my breakdown» не возвращал на `/predictor`.

Следом прошёл ещё один круг по тому же гейту воронки (`a9714b9`, `45e3b24`, `cd8993b`,
`9905461`): слабый тип уезжал гостю рендер-путём (RSC-пропсы при перезагрузке) и
`Set-Cookie`'ом — теперь cookie несёт СВОИ ОТВЕТЫ гостя, а вывод считает сервер, у
которого ключи; пустая проба перестала теряться на перезагрузке и тратить слот
троттла; `/auth` закрыт как назначение редиректа, но `/auth/update-password` —
разрешён, иначе ссылка из письма сброса пароля вела в никуда.

**Живая верификация (2026-08-05):** `npm test` 1928 passed, `tsc` чист, миграции
0058–0060 applied (pending none), прод-смоук гостевого предиктора 6/6 — пустая
отправка заблокирована, в ответе действия `w=null` при `hasWeak=true`, cookie
содержит только номера вопросов, перезагрузка сохраняет пробу без утечки типа в RSC,
`/auth/update-password` отдаёт форму. Волна закрыта окончательно.
